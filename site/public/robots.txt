# robots.txt for vyarno.bg
#
# Three decisions, and the reasoning for each, because the defaults are wrong
# for a product whose data IS the product.
#
# 1. SEARCH ENGINES ARE WELCOME ON THE PAGES.
#    A Bulgarian-language calculator lives or dies on organic search. Someone
#    typing "лична инфлация" or "колко години заплата за жилище" is exactly who
#    the product is for, and there is nothing on the human-facing pages we
#    would rather they did not find. The legal page is indexable on purpose:
#    ЗЕТ чл. 4 wants the provider's identity permanently and directly
#    accessible, and a page search engines are told to skip is one a person
#    cannot find either.
#
# 2. SEARCH ENGINES DO NOT INDEX /data/published/.
#    Not because the files are secret — they are not. The whole repository is
#    Apache-2.0 and public, and these payloads sit in git with their history,
#    schema and refresh dates. This is purely about search quality: a result
#    pointing at hicp_categories.json helps no human reader, and a raw JSON
#    blob outranking the page that explains it is a worse outcome for the
#    person searching.
#
#    Anyone who wants the data by machine should take it from the repository
#    rather than this box: github.com/vyarno-bg/vyarno. It is faster, it is
#    versioned, and it does not cost a small server anything. That route is
#    named in the terms of use too.
#
#    NOTE, because it is the thing people get wrong: the CODE is openly
#    licensed, the FIGURES are not ours to license. Each one carries a
#    source_url and travels under its publisher's terms. See NOTICE.
#
# 3. TRAINING CRAWLERS ARE DECLINED — the whole site, not just the data.
#    The distinction we draw is attribution, not exclusivity, and it is worth
#    being clear that this is NOT a licence restriction: the code is
#    Apache-2.0 and anyone may fork it, including to train on. This asks one
#    specific thing of one specific kind of consumer.
#
#    A search engine sends a person to the number with its source and its
#    date attached. A model trained on the rendered page answers "inflation
#    in Bulgaria is 5.2%" with no date, no source and no way to check — and
#    an unsourced, undated number is the exact thing this project exists to
#    replace. Stating a figure without its provenance is the harm, whoever
#    does it.
#
#    And the limit, stated plainly: this is a request about the rendered site,
#    not a fence around the content — the figures are published, the method is
#    documented and the code is Apache-2.0. It is honoured by operators who
#    honour robots.txt and by nobody else.
#
#    Say the asymmetry out loud, because it is the obvious objection: we take
#    143 district averages from imot.bg. We take them manually, in thirteen
#    requests, only the aggregates the site itself publishes, and we name the
#    source with a link on the page where the figure appears. We are asking for
#    exactly what we give — cite the source — and not for a right of refusal we
#    do not honour ourselves.
#
# 4. THIS FILE IS THE WHOLE POLICY, AND IT HAS TO BE SERVED UNMODIFIED.
#    A CDN in front of the origin can prepend its own managed robots.txt to
#    this one — Cloudflare's "block AI training in robots.txt" setting does
#    exactly that, and the result is a single response with TWO
#    `User-agent: *` groups. RFC 9309 §2.2.1 asks a crawler to merge groups
#    with the same token; parsers that take the first one instead read a
#    catch-all with no `Disallow` and lose the /data/published/ rule in note 2.
#    That is the reason to decline it, and it is a mechanical one.
#
#    The second reason is a claim. The block that arrives with those groups
#    opens «As a condition of accessing this website, you agree to abide by
#    the following content signals» and closes by declaring any restriction in
#    it an express reservation of rights under Article 4 of Directive
#    2019/790. This project does not make that claim and cannot: note 3 says
#    in as many words that what it asks for is NOT a licence restriction, the
#    code is Apache-2.0, and the FIGURES are five publishers' and not ours to
#    reserve. A browsewrap contract term nobody here wrote, contradicting the
#    file it is prepended to, on a site whose terms of use are a ЗЕТ чл. 4
#    document — see docs/legal.md, which is where every claim of right this
#    project makes has to be argued and dated first.
#
#    `Content-Signal:` itself is not in RFC 9309 and no crawler acts on it:
#    Bing Webmaster Tools reports it as syntax it does not understand, and
#    Google has said publicly it has no effect. So the setting costs a
#    warning and buys nothing this file does not already say by name.
#
#    Every crawler that block declines is declined below, so turning the
#    setting off loses no decline. Keep it that way: a name added to a CDN's
#    managed list is a name to add HERE.
#
# robots.txt is a request, not a fence. Everything here is enforceable only
# through the terms of use; see https://vyarno.bg/legal/#terms.

User-agent: *
Disallow: /data/published/
Allow: /

# --- AI crawlers that send a person to the source --------------------------
# Note 3 states a test rather than a category: a consumer that sends a person
# to the number with its source and its date attached is welcome, and one that
# absorbs the figure and restates it without provenance is not. These agents
# are on the first side of it, on their operators' own documentation:
#
#   OAI-SearchBot     «used to surface websites in search results in ChatGPT's
#                     search features» — a search index, not a training crawl
#   ChatGPT-User      fetches a page because a person asked a question
#   PerplexityBot     «It is not used to crawl content for AI foundation models»
#   Perplexity-User   fetches to answer, and «include a link to the page in its
#                     response»
#   Claude-SearchBot  «improve search result quality for users»
#   Claude-User       fetches a page because a person asked a question
#
# (All read from the operators' own crawler documentation, 2026-08-03.)
#
# This is note 3 applied, not note 3 amended. It also settles a position the
# file was taking by accident in three directions at once: Googlebot and
# Bingbot are allowed and have to be — organic search is what a Bulgarian
# calculator lives on — and AI Overviews and Copilot are built on those same
# indexes, so the largest AI answer surfaces were already being fed while the
# smaller ones that cite more visibly were turned away.
#
# **Each group repeats the /data/published/ line, and that is not redundancy.**
# RFC 9309 2.2.1 has a crawler obey the most specific group matching its token
# and NOT merge it with the catch-all, so a group here carrying only `Allow: /`
# would hand these six the raw payloads the group above keeps everyone out of.
# `verify_static_assets.mjs` fails if any of them loses the line.

User-agent: OAI-SearchBot
User-agent: ChatGPT-User
User-agent: PerplexityBot
User-agent: Perplexity-User
User-agent: Claude-SearchBot
User-agent: Claude-User
Disallow: /data/published/
Allow: /

# Google-Extended governs training and Gemini grounding and does NOT govern
# AI Overviews, which are built from Googlebot's index. Declining it therefore
# costs no search surface — and adding it here to leave AI Overviews would not
# work either. That control is a Search Console setting, and leaving Overviews
# means leaving the index that feeds them.
User-agent: Google-Extended
Disallow: /

# Applebot-Extended crawls nothing. It decides how what Applebot already
# fetched may be used, so declining it opts out of Apple Intelligence training
# while Siri, Spotlight and Safari suggestions keep the page — Applebot itself
# is allowed by the catch-all above and must stay that way.
User-agent: Applebot-Extended
Disallow: /

User-agent: meta-externalagent
Disallow: /

User-agent: Bytespider
Disallow: /

User-agent: Amazonbot
Disallow: /

# Cloudflare's Browser Rendering `/crawl` endpoint, which hardcodes this token.
# It belongs here on note 3's own test rather than by association: what it
# returns is page text handed back to a calling program, with no reader at the
# other end for a source link and a date to reach. It is also the one name
# Cloudflare's managed block carries that this file otherwise would not, and
# note 4 depends on that gap staying closed.
User-agent: CloudflareBrowserRenderingCrawler
Disallow: /
